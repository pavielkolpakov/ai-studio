# RAG Module

LangChain 1.0 agent with `read_knowledge_base` + `generate_project_ideas` tools. No embeddings/vector store — knowledge is served as plain text from the `docs/vault/` markdown vault (see `app/vault/loader.py`).

- `chain.py` - `build_agent()` wires `create_agent` with both tools + `GuardrailMiddleware`, injecting the vault routing index into the system prompt (`AGENT_SYSTEM_PROMPT.replace("{index}", load_index())`). `read_knowledge_base(names)` returns the full text of the requested vault notes on demand (via `app.vault.loader.read_notes`); the agent picks note names from the injected index. `stream_response()` emits SSE events: `{type: "tool_call", tool, query}` (`query` is the joined note names for `read_knowledge_base`, else the ideas description), `{type: "token", token, done: false}`, `{type: "ideas", ideas}`, `{type: "done", followups}`. `FOLLOWUPS_ENABLED = False` currently forces `followups: []` on every response; flip it to restore the old behaviour (`pick_followups()` for freeform, `IDEAS_MODE_FOLLOWUPS` when ideas were emitted) — that code is disabled, not deleted.
- `ideas.py` - embedding-free two-step. `select_projects(description)` shows all `docs/vault/projects/` notes (name + title + read_when) to gpt-4o-mini and gets back 2-3 names (`ProjectSelection`); falls back to the first 3 notes whenever fewer than 2 names match, since `IdeasPayload` requires 2+ ideas. `generate_ideas_payload(description)` feeds the selected notes' bodies to a structured-output LLM (tagged `"ideas"`, streaming off) that lightly adapts each; tech/price_range/time_estimate are copied verbatim per prompt instruction. `IdeasPayload`/`Idea` schemas (`ideas` constrained to 2-3).
- `guardrail.py` - classifies + routes every user turn. `classify_turn(messages)` sends the last `CONTEXT_WINDOW` (6) Human/AI messages to gpt-4o-mini and returns `BUSINESS` / `ON_TOPIC` / `OFF_TOPIC` (unknown replies fall back to `OFF_TOPIC`). `before_model`: `OFF_TOPIC` short-circuits via `Command(goto=END, update={messages: [AIMessage(REJECTION_MESSAGE)]})`, otherwise stores the verdict in `GuardrailState.guardrail_verdict`; it skips classification mid tool-loop (last message not Human). `awrap_model_call` (async — `wrap_model_call` has no sync→async fallback and the app runs `astream`) forces `tool_choice=IDEAS_TOOL_NAME` when the verdict is `BUSINESS` **and** the last message is still Human — that Human check is what stops the ideas tool re-firing forever on the follow-up call that writes the intro text.
- `prompts.py` - `AGENT_SYSTEM_PROMPT` (persona + tool-use instructions; `{index}` placeholder filled at agent-build time; it does not tell the model when to call `generate_project_ideas` — the middleware forces that) + `GUARDRAIL_PROMPT` (3-way BUSINESS/ON_TOPIC/OFF_TOPIC classifier over a short transcript; elaboration on an already-scoped business is ON_TOPIC, not BUSINESS). `IDEAS_SELECTION_PROMPT` (pick 2-3 project names from the catalog menu) + `IDEAS_GENERATION_PROMPT` (adapt the selected entries, copying tech/price/time verbatim).
- `followups.py` - `pick_followups(user_msg, assistant_msg)` calls gpt-4o-mini with strict JSON schema to pick 3 ids from `app.data.followup_pool.PICKABLE_IDS`. Returns `[]` on any failure - frontend renders nothing then appends Book a Call via <2-fallback. Currently unreachable behind `FOLLOWUPS_ENABLED`; kept intact and still tested.
